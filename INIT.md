# Odin-Skills — project init card

> **Read this first when starting or switching into this project.** It asserts *this* project's
> purpose, scope, and invariants so no other project's assumptions bleed in. Do not import scope,
> cut-lists, or decisions from any other `projects/*` subtree, and do not import the harness's own
> conventions where this file contradicts them. Each project owns its own truth.

## Purpose

Odin-Skills is a **distribution monorepo**: the one-way published mirror of the skills the Odin
harness owns, packaged as one installable Claude Code plugin and — per
[`docs/adr/0001`](docs/adr/0001-distribution-monorepo-and-per-skill-repos.md) — additionally as one
small read-only repository per skill, so a user can take a single skill without the bundle.

It exists because the harness vendors far more skills than it authors. Redistributing all of them
would republish third-party work Odin has never touched; redistributing none of them would strand the
work Odin *is* the author or maintainer of. This repository is exactly the second set: seven skills
authored here and ten forked from upstream and substantially modified.

Nothing is developed in this project. It packages, licenses, validates and publishes what the harness
produces.

## Scope

**In scope**

- Packaging — the plugin manifest and marketplace entry under `.claude-plugin/`.
- Licensing — per-skill upstream `LICENSE`/`NOTICE` artefacts, the two repository-level license
  files, and the licensing tables in `README.md`.
- Provenance — `docs/PROVENANCE.md`, the root `NOTICE`, and each fork's `UPSTREAM.md`.
- The validator (`scripts/validate-skills.sh`) and its test matrix.
- The sync and publish scripts, and the publishing procedure in `docs/PUBLISHING.md`.
- This project's own `README`, `CHANGELOG`, `CONTRIBUTING`, `SECURITY`, `MISTAKES.md`, ADRs and
  roadmap.

**Out of scope**

- **Authoring or editing skill content.** Every `SKILL.md`, reference and script under `skills/` is
  a copy. It is written in the harness's `.claude/skills/` and reaches this project only through
  `scripts/sync-from-odin.sh`. A change made here is destroyed by the next sync.
- Skills the harness merely vendors and has not modified — they are not redistributed here.
- Harness governance: `CLAUDE.md`, the harness ADR sequence, and the harness inventory counts do not
  apply to this subtree, and nothing added here may move a harness `# expect N`.

## Invariants

1. **Sync direction is always Odin → Odin-Skills.** One-way and mechanical. There is no path back;
   an edit made in `skills/` is not a contribution, it is a change that will be silently reverted.
2. **`scripts/validate-skills.sh` is the gate.** It must exit 0 before any publish — frontmatter,
   manifest parity, licensing, provenance and reference reachability.
3. **The subtree stays in the harness.** It is not removed after extraction, because
   `.claude/scripts/vendor-skills.sh` derives its refresh-protection list from
   `projects/Odin-Skills/skills/` — deleting the subtree would let a vendor refresh overwrite every
   fork. `docs/PUBLISHING.md`'s optional removal step is deliberately not executed.
4. **Ids here are this project's own sequence.** `docs/adr/` starts at 0001 and `docs/roadmap/`
   counts from RM-0001, both independent of the harness sequences. Cite them from outside as
   `odin-skills:ADR-0001` / `odin-skills:RM-0001` (harness ADR-0050, `projects/README.md` rule 7).
5. **`.github/workflows/` stays manual-dispatch** while the subtree lives in the harness. A workflow
   under `projects/*/.github/workflows/` with an automatic trigger trips Layer 1D of
   `.claude/hooks/odin-safety-guard.sh` and blocks every git write in the whole monorepo. Automatic
   triggers are restored in the same change that publishes this directory as its own repository.

## Memory namespace

- claude-mem namespace: **`task:odin-skills`**. Write this project's facts here only.
- Never write them to `odin-operational` or to another project's namespace.
- The authoritative, reset-proof record is this project's own files: this `INIT.md`, `docs/adr/`,
  `CHANGELOG.md`, and `MISTAKES.md`.

## Gates

Run from this directory. All three must be green before a publish.

```sh
scripts/validate-skills.sh          # frontmatter, manifest parity, licensing, provenance, symlinks
scripts/tests/validate.test.sh      # the matrix proving each of those checks actually fires
scripts/sync-from-odin.sh --check   # fail if the mirror has drifted from the harness
```

The roadmap is gated separately, from the harness checkout:

```sh
cd .claude/skills/roadmap && python3 -m scripts.roadmap --root projects/Odin-Skills validate
```
